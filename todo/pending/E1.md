## 1. The handler, read

`tables/vm_opcodes.json` gives op 92 handler **0x00404590**, length 2, tag
`OBJECTS`. It has no `proc` label and is not in `readable/` or `Runtime.exe.c`
(the CLAUDE.md §1 trap — nothing calls it, it is a dword in the dispatch table),
so it was read with `python3 tools/asmfn.py --op 92`. In order:

| step | the assembly | what it means |
|---|---|---|
| 1 | `mov dl,[eax]` / `mov dh,[eax-1]` / `movsx esi,si`; `test esi,4000h` → `movsx esi,[eax+esi*2+2]` | one int16 operand, the usual `0x4000` indirect bit through the parameter block at `ctx+0x24` |
| 2 | `mov eax, dword_6A05E0` … `jnz loc_404779`, with `or byte [ecx+28h],10h` before it | **`g_ScriptDryRun` skips the whole handler**, announcement included. The `ctx+0x28 |= 0x10` bit is set either way |
| 3 | `push offset aObjects` / `push esi` / `call sub_40EC70` | `Dbg_LogTagged(id, "OBJECTS")` — the announcement the golden traces record |
| 4 | `cmp esi,0FFFFFFFFh; jz` | `-1` returns before anything is read |
| 5 | `push esi; call sub_409AE0` | `ObjectRecord_Read(id)` → the 1304-byte `IAM\OBJECT` record in `ebx` |
| 6 | `mov eax,[dword_930724+194h]`; `cmp eax,3` / `cmp eax,0Fh` → `sprintf(buf,"{C}%s",ebx+118h)`, else a `rep movsb` of the same field | the SUBTITLE, from `rec+280` (the description). `+0x194` on `g_PlayerActorRec` is int slot **101 = `ACTOR_STATE`**, so the `{C}` prefix is conditional on the player being in state 3 or 15 |
| 7 | `lea esi,[ebx+0Eh]`; `sprintf(dword_4E6C30,"%s.ADP",esi)` | **the stem is `rec+14`** |
| 8 | `if (dword_93072C && dword_4E6C88) { I2D_FreeBitmap; clear both; [player+194h] = 1 }` | a media bitmap already up is torn down first, and the player leaves the image state |
| 9 | `cmp word ptr [ebx+2],10h; jnz loc_404701` → `sub_40BB40(stem)`, `sprintf("IMAGES\\%s")`, `I2D_LoadBitmap`, `[player+194h] = 0Ah` | **kind 16 is a DOCUMENT**: a full-screen bitmap and `ACTOR_STATE` **10** (`ImageScreen`, `src/actor/state.h:68`). `sub_40BB40` appends the constant at `0x004C0D24` = `".BMP"`. **This arm plays no audio at all** |
| 10 | `repne scasb` … `cmp ecx,4; jbe loc_404763` | `strlen(name) <= 4` is REFUSED — an empty stem builds `".ADP"` and nothing plays |
| 11 | `cmp eax,544F565Ah` (`'ZVOT'`) / `cmp eax,504F565Ah` (`'ZVOP'`) → copy the 13 bytes at `0x004C0868` over the name | **the substitution.** `dd 474E494Ah, 3346464Fh, 5044412Eh, db 0` = **`"JINGOFF3.ADP"`**. A raw dword compare, so it is **case-sensitive** |
| 12 | `push offset dword_4E6C30; call sub_41B200` | the play |
| 13 | `Mem_Free(rec)`; `Subtitle_Show(unk_4E6268)` | |

And `sub_41B200` (`readable/src/04_sys.c:5869`) is **not the sound bank**:

```c
if (byte_91030C)                       /* the audio system is up */
{
    Morph_Stop();                      /* <- ONE media voice at a time */
    Morph_ResetTracks(0, 0, 0, 0, 0);
    sub_42BC10(0); sub_42CC30(1);
    Morph_SetAudioFormat(0x5640u, 1u, 30);   /* 22080 Hz, MONO, 30 fps */
    sprintf(Buffer, "VOICEOFF\\%s", a1);
    Morph_Start(Buffer, 0);
}
```

A voice-over goes through the **morph streamer** — the same one a `.3DM`
dialogue line uses — with no morph tracks, one channel. The leading
`Morph_Stop` is why the port keeps one handle and stops the previous shot.
`byte_91030C` is the audio-system flag, set in `Game_Init` and also gating
`Music_PlayTrack`; the port ignores it for the same reason `MusicPlayer` does.

The other caller of `sub_41B200` is `Game_HandleEvent` **case 47**
(`readable/src/01_file.c:1844`): reading a document shows `rec+280` with an
`{I255000000}` colour prefix and plays **`JINGOFF2.ADP`**.

## 2. What the data then says — and the finding

**`docs/CUTSCENES.md` §5 and `verify.py: cutscene music` say the cutscene voices
"cannot be played from this tree". The two numbers they rest on are right and
the conclusion is wrong.**

| | |
|---|---|
| ZVO objects (`IAM\OBJECTS.TAG` name begins `ZVO`) | **561** |

`JINGOFF3.ADP` ships (22949 bytes) and is **real audio, not silence**: 45898

Of the 17 files: 10 are named by an object stem, `JINGOFF2` and `JINGOFF3` by

the six dead spell recipes on the shipped-and-unreachable list.

**The Impasse cutscene's four voices all play**: 142 `ZVOD001` (3.36 s) and 141

## 3. `media.play` announces — and the traces are a TIER-4 oracle for it

`tables/vm_announce.json` row 92: `{"domain": "OBJECTS", "field": 0}`. So yes,
op 92 announces, to `OBJECTS`, field 0, and the accessor a viewer polls is
**`Session::announced()`** (`src/script/area.h:370`), which is append-only —
`announced_` is never cleared — so a cursor is the whole mechanism.

**Better than expected**: `aObjects`, the literal the handler pushes, is at
**0x004C0844**, and the image contains **exactly one** `push offset aObjects`
(`Runtime.exe.asm:5528`; the address is fixed by the `aCS`/`aSAdp_0`/`aImagesS`
run between it and `dword_4C0868` at 0x4C0868). Every other `OBJECTS` announcer
pushes a different copy. So **a trace line naming `004c0844 "OBJECTS"` is
`media.play` and nothing else**, and the existing captures already carry the
engine's own media ids:

```
$ grep '004c0844 "OBJECTS"' traces/impasse-walk.log | ...

746 745 748 751 750 747 743 407 411 170 465 611 673 425 792 793 794
```

102 announcements across the eight non-empty traces, 56 distinct, **56 of 56**
resolving to a ZVO-tagged object through this rule. The Impasse cutscene's
first four after the ubiquitous 997 are **142, 141, 404, 410** — exactly the
task's four, in order. And its one kind-16 id, **715 "ZVO G001 TITRE"**, has
`gamedata/IMAGES/zvog001.bmp` on the disc: the document arm, exercised by a capture.

*(997 is `ZVO P660 Vide Pas Traduire` — "empty, do not translate" — and it

### 3a. THE ONE THING THE SESSION CANNOT TELL THE VIEWER — a proposed accessor

`omk::Announced` is `{std::string domain; std::int32_t value;}` and carries **no
opcode**, while **ten** opcodes announce to `OBJECTS`: 49, 50, 51, 52, 66, 67,
76, 77, **92**, 143. A domain-only filter would fire a voice on every
`inventory.add`.

**Minimal proposal for whoever owns `src/script/area.h` (T11, or wave B's
T16).** One defaulted field and one word at the push site — no other call site
changes, since `Announced{domain, value}` still aggregate-initialises:

```cpp
 struct Announced {
     std::string  domain;
     std::int32_t value = 0;
+    // WHICH handler narrated it. `Announced` was domain+value until a viewer
+    // needed to tell `media.play` (92) from the nine other opcodes that
+    // announce to OBJECTS; the golden traces distinguish them by the string
+    // LITERAL's address, which a port has no equivalent of.
+    std::uint8_t op = 0;
 };
```
```cpp
 // area.cpp, Session::record
-            announced_.push_back({it->second.domain, c.fields[f]});
+            announced_.push_back({it->second.domain, c.fields[f], c.op});
```

**Until that lands the port is not blocked, and the fallback is measured rather
than assumed.** `VoiceOverPlayer::poll` is a template with
`if constexpr (requires { a.op; })`: with the field it takes op 92 only and is
exact; without it, `domain == "OBJECTS"` plus a ZVO tag name. Over the whole
world-script corpus — both archives' zone scripts, their second tables and the
`+4` startup scripts — op 92 has **2605** sites and **all 2605** name a ZVO
object, while the other nine have **1584** between them and **exactly one**
names a ZVO object: `inventory.remove_all 111` ("ZVO P006 Rien Partic"), AREA 65
at pc 3564. **One false play in the whole shipped game**, named here so nobody
has to find it again. The template flips to exact with no caller change.

## 4. What was delivered

`omk::VoiceOverLibrary` — `IAM/OBJECT` (through the existing
`script/objects.h` reader) plus `IAM/OBJECTS.TAG` (a 25-line ini scan; the
handler never opens it, so it is optional and only `isVoiceObject` degrades).

* `resolve(fs, id) -> VoiceOver{object, objectName, stem, image, file,
  substituted, path, shipped}` — steps 4–11 above, in the handler's order;
* `decode(fs, tables, v) -> std::vector<int16_t>` — mono, 22050, via the
  existing `adpcmDecode`; `decodeById` for a one-line caller;

## 6. The `play.cpp` hook (E2 owns the file)

Three additions. **Where**: `engine/backends/sdl/play.cpp`, in the viewer's
frame loop, immediately **after** the `session.musicTrack()` block that follows
`session.frame()` (~line 1680 as the file stands) — the same place music is
polled, and after the frame so a script that fires `media.play` this frame is
heard this frame.

```cpp
// (a) with the other includes, near "audio/music.h"
#include "audio/voiceover.h"
```

```cpp
// (b) beside `adpcmTables` / `music`, once, before the loop
omk::VoiceOverLibrary voiceLib;
voiceLib.load(fs);
omk::VoiceOverPlayer voices(voiceLib);
int voiceShot2 = -1;              // the ONE media voice, per Morph_Stop
```

```cpp
// (c) THE HOOK - right after the music block
//
// `media.play` is an EVENT, not a level like music: each announcement is one
// play, and `sub_41B200` opens with `Morph_Stop()`, so a second one CUTS the
// first. That is the whole of the engine's policy here.
for (const int mediaId : voices.poll(session.announced())) {
    const auto vo  = voiceLib.resolve(fs, mediaId);
    const auto pcm = voiceLib.decode(fs, adpcmTables, vo);
    std::printf("media.play %d (%s) -> %s%s, %.2f s\n", mediaId,
                vo.objectName.c_str(),
                vo.file.empty() ? (vo.image ? "IMAGES\\" : "nothing")
                                : vo.file.c_str(),
                vo.substituted ? " [JINGOFF3 substitution]" : "",
                static_cast<double>(pcm.size()) / omk::kAdpcmRate);
    front.stopSound(voiceShot2);
    voiceShot2 = pcm.empty() ? -1
        : front.playSound(resampleToDevice(pcm, 1, omk::kAdpcmRate, 44100));
}
```

Notes for whoever lands it:

* **keep the handle**, and stop it where a new area or a conversation starts —
  `front.stopSound(voiceShot2); voiceShot2 = -1;` beside the existing
  `session.loadArea(...)` call and beside the dialogue's own
  `front.stopSound(voiceShot)`. A voice-over and a dialogue line are two
  different shots and the engine would never have both: `Morph_Stop` is one
  player.
* **`voices.skip(session.announced())` right after `session.loadArea(...)`** if
  the backlog of an area's startup announcements should not all fire at once.
* `resampleToDevice(pcm, 1, ...)` — **channels is 1**. `Morph_SetAudioFormat`
  says mono, and `resampleToDevice` duplicates it to both device channels.
* the `printf` is the useful half while there is no subtitle layer: it names
  the object, the file and whether the jingle was substituted.

## 9. A paragraph for `docs/CUTSCENES.md` — REPLACING the "missing voices" text

## 11. What I could NOT establish

* **Whether `Announced` should grow `.op`, or a dedicated list.** §3a proposes
  the field; I could not measure the cost because `area.*` was T11's. The
  fallback is measured and the template flips with no caller change.
* **Why the subtitle is CENTRED in states 3 and 15.** `{C}` is settled —
  `docs/UI.md` line 1224 and `docs/FILE_FORMATS.md` line 890 both give it as
  one of the four alignments, centring — so the handler centres the subtitle
  exactly when the player's `ACTOR_STATE` is 3 (shoot mode) or 15, and
  left-aligns it otherwise. **What is open is WHY those two states**: 3 is
  `Shoot_Enter`'s and 15 is not named in `src/actor/state.h`'s list beyond its
  number. I did not trace `Subtitle_Show` (`sub_41E040`) to see what else
  differs, and the port draws no subtitle, so nothing here depends on it.
* **Why object 997 ("ZVO P660 Vide Pas Traduire" — *empty, do not translate*)
  is announced in every capture, `menu-noinput.log` included.** It has a `ZVOP`
  stem, so the engine plays the 2 s jingle for a voice explicitly marked empty.
  Either it is a deliberate "clear the subtitle" call whose jingle is an
  accident of the substitution rule, or the substitution is narrower than the
  assembly reads. The assembly is unambiguous and the corpus cannot separate
  the two, so it is recorded, not resolved.
* **Whether the `strlen <= 4` refusal ever fires in the shipped game.** No ZVO
  object has an empty stem, so it is a dead branch against this corpus; ported
  anyway and recorded rather than trimmed.
* **How loud, and where.** `Morph_Start` hands the buffer to DirectSound; the
  attenuation and pan law has no reachable tier (PORTING B5), the same position
  the audio row already takes.
