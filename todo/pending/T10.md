## 1. `docs/SCRIPT_VM.md`

**"### Operand encoding" — rewritten.** The shared fetch (`sub_401AA0`
0x00401AA0 and its inlined copies) indexes the block at `ctx+36` **from its
second word** — `movsx eax, word ptr [edx+eax*2+2]` — so operand `0x4000` is
`args[1]`. `Message_RunHandlers` writes `args[0] = message id, args[1] =
sender`, so `push.i16 0x4000` pushes the **sender**. The corpus is the
independent half: all **59** indirect operands in the world scripts are
`push.i16 0x4000`, all 59 sit in the 7 scripts that are message subscriptions
(AREA 2/61/141 msg 3, AREA 144 msg 2, SCENE 56 msg 3, GLOBAL msg 4 and 20), and
each is compared with `cmp.eq` against an actor id (173, 187 …) or an object id
(3, 100, 385, 775 …) — never a message id. `Script_NewContext` zeroes `ctx+36`
everywhere else, so no other script *could* carry the bit. Also here: the
verified list of the **91** opcodes that run the fetch (89 from the blocks, plus
op 6 whose block is empty and op 120 whose block is the wrong function), the
note that 15's value / 17's and 71's both fields / 47's three all go through it,
and that only `0xFFFF` is excluded so any other negative operand would be taken
as an index. *(Correction to issue 20, which read `0x4000` as the message id;
T1 reached the same correction from the port side.)*

**New: "## The context status word, and what resumes a parked script".** The
eleven values of `ctx+22`, who writes each and what writes 1 back — events 2
(fight), 3 (object/move), 4 (camera), 5 (screen), `Script_Pump`'s tail (8 and
10), `Script_ProcessActions` (9), with the pump's tail quoted. **Status 5 is in
the table and marked unresolved**: `Area_Transition` mode 0 state 4 writes it
into the *superseded* caller and nothing found writes it back. Then the ten
opcodes that write the word (3, 45, 46, 58, 60, 62, 70, 89, 96, 126) with the
value each writes — including that 96 parks **only when the travel is
non-zero** and 126 unconditionally — and why op 152's apparent eleventh write is
its unbounded block. Then the activate dedupe (`ctx+32` cleared in
`Script_Execute`'s `LABEL_8` only when an activate finishes at status 0, so the
rule is "no second activate while the first is unfinished"), the **one-shot
latch** (bit 15 latches the slot into the 4↔5 ping-pong between the pump and
event 7 — it does **not** free the zone while the player stands in it), and the
**`Script_Pump` state-2 transcription fix** (the dry run decides only whether
the press is consumed; action 2 is queued on both outcomes).

**Corrected in place:** "starting a conversation ends the tick" — it ends it for
**that one context**; the pump's loop carries on and the world stops on the
*next* frame at `if (g_DialogState != 1)`.

**New: "### 93 — `actor.stat.set`, the opcode named after its side effect".**
Handler 0x00404790, three fetched fields (actor / property / variable),
`Var_Get(field 2)` then `Actor_SetProperty` on **both** arms; `Hud_ShowValue` is
the player arm's first call and the source of the old name, but it returns 0 for
anyone but the player and for properties 4/5 while the write happens either way.
The exact mirror of 86. The op-93 rows in the two hand-written tables are
renamed with it.

**New: "## The area transition — `Area_Transition`'s state machine".** The two
resident slots (`0x0069BC40`, two 16-byte rows of {AREA block, SCENE block,
area id, scene id}, everything walking both), the 8-dword block at
`dword_6A0600`, the five modes (op 47, op 48, `Script_QueueAction`'s action 3,
`Script_Pump`'s tail, event 3) and every state edge as a table; the departure
and arrival objects as objects of the **outgoing** block; op 45's status-8 park
and the `dword_4C0130` deferral that makes `Script_Execute` refuse any further
45/47; **the resident-return branch of `Area_LoadIntoSlot` that never reaches
`Area_TickLoad` case 9**, so no startup script and no `Zones_RegisterAll` on
A → B → A; the nine-case staged load and its `sub_41EFA0` gate; the 60-second
watchdog and its status 11. Port status marked per part.

**New: "## Messages, and the handler's parameter block".** Event 43 (**28 sites**
— counted, not taken on trust), the scene → area → global search, the 8-byte
block, message 25 inline and the rest queued as actions 1 and 4, message 0's
`byte_4C012C` stamp, and the tie back to the indirect operand.

**New: "## A note on site counts".** Counts in `docs/` are over the **5785**
world slots including `IAM\GLOBAL`; `todo/iam-script-engine.md` counts
AREA + SCENE only and is lower by exactly GLOBAL's share (93: 754 + 27 = 781;
86: 431 + 28 = 459; 120: 235 + 20 = 255; 89: 545 + 3 = 548; 68: 208 + 18 = 226;
indirect operands 22 + 37 = 59). The port's sweep enumerates **5958** slots and
reports higher figures again (T8's 814 for op 93). **I could not reproduce 814
or 460 from any enumeration here**, so rather than write a number I cannot
derive, the doc names the three corpora and says they have not been reconciled.
Someone should — it is a one-line diff between two slot walks.

**Also corrected in place:** the "## Open" bullet claiming the `0x4000`
indirection is never exercised (true of the 754 dialogue operands it was

## 2. `docs/GAME_STATE.md`

* **§2, after the accessor table:** `ObjectState_Get`'s sign extension (T6's
  finding — state 3 at `i % 4 == 3` reads back −1; nothing in the game can see
  it because every consumer masks), then **"### Which VM opcode writes which
  array"** — the table the task asked for, one row per array, every writer
  attributed to the accessor call found in its handler block, with full-corpus
  site counts. Four notes under it: op 93 is deliberately absent (it writes an
  actor record, which is only in the block for the player); the `ObjectShown`
  index is the **character record's `+18`**, not the object id, and
  `character.hide -1` hides the **player** and writes no bit (T2); five of the
  arrays have no other script-side writer, so stubbing those opcodes freezes
  them at `IAM\START`; and the scene-per-area entry is what makes `scene.load`
  survive a save.
* **§3:** T6's "What the four opcodes do to a list" — the front insert, the
  per-list duplicate refusal, the parallel 56-byte record array that is a cache
  and not state.
* **§4:** `player.become`'s actual copy (`strcpy` of the two bios, `rep movsd`
  of 0x43 dwords into `+68`), so `+272` is the player's actor id: −1 in
  `IAM\START`, 136 `KUM_FN` after AREA 118's startup script (T2).
* **§6:** the clock's unit derived as a **millisecond** (166 per 5 frame units,
  `Timer_Format`'s /1000, op 113's ×1000).
* **New "## The script timer"**, placed between §6 and §7 and deliberately
  **unnumbered** so that "GAME_STATE 7/8/9/10" — which `verify.py` and
  `CLAUDE.md` both cite — keep meaning what they meant. T6's table of 110–115,
  the inversion evidence, the flag bits, and that expiry **posts message 18**
  through `Game_RaiseEvent(43, …)`.
