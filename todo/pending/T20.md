## 1. What changed in `play.cpp`, by function, and the rule each piece follows

### The one `speaker*` body became a list

Removed: `speakerRest`, `speakerPosed`, `speakerTex`, `speakerFace`,
`speakerPelvis`, the file-global `sceneTracks`/`sceneClipWas`. What is left
under "THE SPEAKER" belongs to the LINE, not to a body: `speakerModel`,
`speakerVoice`, `speakerTracks` (the `.3DM`), `speakerMorph`, the camera solve
(`speakerAt`, now with `speakerSolved`).

Added, beside them:

* `struct CharModel` — one `.3DO`/`.3DT` per MODEL NAME (`rest`, `meshes`,
  `tex`, `face`, `root`, `texBase`), held in a `std::map<std::string,
  CharModel>`. Shared by every actor wearing it: the alley's three passers-by
  are one `PA1_FN`. Node-based map, so a pointer into it survives later
  inserts.
* `struct CharBank` — one `.CTL` per BANK NAME plus `idleClip`, the entry
  `Actor_LoadModel` → `Actor_LoadBankList` leaves the channel on. The
  resolution is `PlayerController`'s constructor transcribed:
  `Cef_DefaultGroup` is the group whose `flags` bit 0 is set, `Cef_DefaultEntry`
  its `defaultEntry`, then `clipOwner()`'s chain — an entry whose flags carry
  `0x8002` is an alias and hands the clip on through its GoTo.
* `struct Staged` — one per actor id: `posed` geometry, `at`/`facing`,
  `placed`/`pelvis`, the per-actor scene-clip cache, the idle tracks, the
  seat, and the pose source for the log. Held as
  `std::vector<std::unique_ptr<Staged>>` — **never** a `vector<Staged>`: the
  Vulkan backend caches a vertex buffer by (pointer, revision), and a
  reallocation would hand it a moved object. `posed.revision = ++worldGeoRev`
  every frame it is drawn, so a freed address that is reused can never carry a
  revision the backend has already seen.

### `charModelFor` / `charBankFor` / `idleTracksFor` (new lambdas)

`idleTracksFor` is `PlayerController::poseTracks()`'s recipe transcribed: a
`.CTL` clip is an `.ani` DESCRIPTOR with no `"3.0V"` wrapper, its tracks resolve
to meshes by name, and **key 0 is the rest sentinel** so frame `f` reads key
`f + 1`. Only frame 0 is built — nothing here ticks a channel per actor.

### The sync, replacing "WHOEVER IS ON SCREEN"

Was: `if (!session.shown().empty() && speakerModel.empty())` — load
`front()`'s model, once. Now: every `Session::Shown` gets a `Staged`; a
`fromTable` row supplies `pos`/`facing` (a placement record names a spot on the
GROUND, so the anchor is the FEET); a row with `fromTable` false carries no
position, because `Session::showCharacter` pushes a bare record, and such a
body waits for a program path or a camera solve. In adventure mode the actor
equal to `session.playerActor()` is skipped, because the controller owns that
body — so he is not drawn twice. A body no longer in `shown()` is dropped, and
a model no staged body wears leaves the pool.

The conversation's speaker is staged even when no table places him and no
script shows him: keyed on `dialogue().conversation().speaker` (the DIALOG
chunk's word 0), falling back to a model-name match, and placed from the
camera solve when nothing else has placed him.

### The pose source, resolved PER ACTOR

The bug issue 41 names is here. The old loop took the LAST running `"actor"`
program for the one body:

```
for k in sc.started(): if how=="actor" && clip>=0 && running: sceneClip = ...
```

Now each `Staged` looks for the program that drives IT:

* `how == "actor"` → `Started.actor == s.actor` (`ScriptObject_StartOnActor`
  puts the CHARACTERS id in the call's first field);
* `how == "player"` → `s.actor == session.playerActor()`. **This was found by
  rendering**: keying on `"actor"` alone left Kay'l in his idle through his own
  arrival, because the Impasse's `A_1_KaylArrives` is a `scx.play.player`
  program and sets no `Started.actor` at all;
* a running program whose actor is nobody on screen drives the frame's ONLY
  body — LABELLED as a reconstruction. AREA 118's arrival needs it (the shown
  list carries Kay'l as 310, the program names another id) and it can never
  mis-assign once there is more than one body, which is the case the issue is
  about.

Then, in order: (a) that program's clip on its authored `.3DP` path
(`Path_Sample`, mode 1 LINEAR, plus the call's inch offset — the existing code
moved into the per-character loop); (b) the conversation line's `.3DM` and its
face, with `sub_42D120`'s two-sided fade unchanged and the root NOT cancelled
when a scene clip stages him; (c) the bank's default entry at frame 0; (d) the
rest pose.

### The anchor — and one correction the pictures forced

`composePose` leaves a hierarchy ROOT at its authored position, and character
models are **not authored about the origin**: `HO1_FN`'s `UBassin` is at
(2.9, −2.4, 17.9) but `DE1_FN`'s `D1Bassin` is at (507.1, −168.1, 39.2). The
old code placed the model ORIGIN on the placement, so the Demon drew 507 units
up the alley (measured: box x 8060..8164 for a placement at 7604). The pelvis
is what a placement names — the rule CLAUDE.md 6 settled for the web
viewers — so the model's own root offset is subtracted first. It also moves
the intro speaker by (2.9, ·, 17.9), which is why the intro frame is no longer
pixel-identical (§3).

Height: an authored PATH names the pelvis and its height is kept; a placement
record and a camera solve name the ground, so the FEET go there (largest y —
the game's Y points down), seated on `floorUnder(playerSoup, x, y−1, z)`,
which is `walk_set.cpp`'s own `seatOnFloor` direction. **The seat is taken
ONCE**, when the pose source or the clip changes, and the clip's root motion
moves him from there — re-seating every frame cancels every vertical a clip
has, so a jump would slide along the ground. If the walkable floor is more
than a body height (100 units) below the authored point the authored y is kept
and a line says so; that cut-off is this file's, not the engine's.

Facing (`Actor_SetEuler`) is applied only to a body no clip is turning: a
scene clip carries its own root orientation and a line's root is relative to
the actor's own frame.

### The texture pool

`worldTex`, then one section per staged MODEL (`CharModel::texBase`), then the
player's (`playerTexBase`), then the sprites' (`spriteTexBase`) — a batch's
slot is its material plus its owner's base, the engine's own indexing (the
bucket key's low six bits, ASSETS 4b). Rebuilt on a **composition** counter
(`poolComposition`, bumped by `rebuildWorld`, by a model loaded and by a model
dropped) plus the two booleans for the player and sprite sections — **not** on
the total size, which is exactly what cannot see two models of equal texture
count swapping. The pool prints one line per cast change, and warns once when
it passes 64 slots (it does: 154 with the sprite section resident, which is
pre-existing — the old pool was `worldTex + charTex + spriteTex` and overflowed
the same way).

### The draws, the set pieces, the summary

Every `drawn` body's batches are pushed with its own base; the player's now
uses `playerTexBase` instead of `worldTex.size()`. The mirror, letterbox,
camera and bucket-sort code is untouched. `setPieceLinks` type 2 (the
three-letter model tag, `sub_450FC0` case 2) now scans every staged body and
returns ITS position, falling back to the player. The exit summary gains
`staged N characters (ids …)` and one row per body still on screen.

### Two instrument additions

* `--eye` / `--at` / `--fov` now override the camera **with the Session
  running**, not only under `--scene`. Labelled in the code as an instrument
  and nothing the engine does. Without it none of the pictures below could be
  taken: the game's own beat cameras do not frame the bodies (§3).
* `OMK_STAGE_PROBE=1` prints, every 100 frames, each drawn body's world AABB,
  corner and batch counts and the live camera. That is what located the
  507-unit pelvis offset.

## 6. What stays labelled

* **The idle is frame 0 of the default entry's clip, not a running channel.**
  Nothing here ticks a `CefChannel` per actor: an idle body is a still.
* **The lone-program fallback.** A running program whose actor is nobody on
  screen drives the frame's only body. AREA 118 needs it; it is a
  reconstruction, not a rule read out of the engine.
* **The 100-unit floor cut-off** for keeping an authored y instead of the
  probed floor is this file's, not the engine's.
* **The seat-once rule** is the engine's shape (seat, then `Actor_MoveBy`),
  but where a clip's vertical ends up is not verified against anything.
* **No look-at, no shadows, no per-actor `.CTL` runtime, no `Actor_SetEuler`
  from `Started::euler`** (still unported, so a scene-driven body keeps only
  its clip's root rotation).
* **`--eye/--at/--fov` in Session mode is an instrument**, not a slice of the
  port.
* **The 64-slot ceiling.** A bucket key addresses 64 textures and the pool
  reaches 154 with the sprite section resident. Pre-existing, now reported
  once per run.

## 7. Found wrong in issue 41 or in T19's API

* **Issue 41's fix shape says "the running scene program whose `Started.actor`
  is this actor".** That is not enough: the Impasse's `A_1_KaylArrives` is a
  `scx.play.player` program, `Started.actor` is −1 for it, and Kay'l is the
  player. The `"player"` arm has to map to `session.playerActor()`.
* **The brief's "the three passers-by 212/218/219 (`PA1_FN`)" cannot be
  drawn.** `PA1_FN.3DO` is 1236 bytes: one mesh, `PBassin`, 8 vertices,
  12 triangles, flags `0x1` — rejected by the engine's own drawable mask
  `flags & 0x800043`. They have no body in the shipped data, so the question
  "a balcony or a window?" cannot be answered from a picture. Their authored
  y −239 is 160 units above the alley floor (−79), which the code now reports
  rather than silently seating.
* **T19's `Shown::pos`/`facing` are zero for a script-shown actor** —
  `Session::showCharacter` pushes a bare record — so `fromTable` is load-bearing
  for a frontend and `pos` must not be trusted without it. Handled here; worth
  a sentence in `area.h`.
* **`Shown` carries no flag for "this is the player's body"**, so a frontend
  must compare against `session.playerActor()` itself to avoid drawing him
  twice.
* Not a fault, but a trap that cost three runs and is already in CLAUDE.md 5:
  **this is zsh, and `set -- $var` does not word-split**, so a camera passed
  through a shell variable silently arrives as one argument and the override
  is skipped — the frame then looks broken and is merely un-overridden.
