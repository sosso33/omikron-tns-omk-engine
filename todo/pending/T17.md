## 1. What the engine says

`Cef_TickChannel` 0x004A853A..0x004A85B3, from `Runtime.exe.asm` (the
decompilation is 29_win32.c 300-320, `LABEL_75`):

```
loc_4A853A: mov  ecx, [esp+40h+var_30]   ; the word, after the latch and the
            test ecx, ecx                ; walker-edge loop have masked it
            jnz  short loc_4A854B
            mov  ecx, 40000000h          ; wholly consumed -> the idle word
            mov  [esp+40h+var_30], ecx
loc_4A854B: cmp  ecx, [esi+14h]          ; == lastInput_ ?
            jz   loc_4A81E4              ; nothing to commit
            mov  [esi+14h], ecx          ; lastInput_ = word

            cmp  eax, 0Fh

            jz   short loc_4A8583
            cmp  eax, 1
            jbe  short loc_4A8586
            mov  dword ptr [esi+18h], 1  ; (2) count = 1, and no push
            jmp  loc_4A81E4
loc_4A8583: cmp  eax, 1
loc_4A8586: jnz  short loc_4A859A
            test dword ptr [esi+1Ch], 40000000h
            jz   short loc_4A859A
            mov  dword ptr [esi+1Ch], 0  ; (1) queue[0] = 0
            xor  eax, eax                ;     n = 0
loc_4A859A: test eax, eax
            jz   short loc_4A85A6
            jbe  short loc_4A85AB        ; dead: CF is 0 after test eax,eax
            cmp  [esi+eax*4+18h], ecx    ; queue[n-1] == word ?
            jz   short loc_4A85AB
loc_4A85A6: mov  [esi+eax*4+1Ch], ecx    ; queue[n++] = word
            inc  eax
loc_4A85AB: mov  [esi+18h], eax
```

`+18h` is the count and `+1Ch` the first word, so `[esi+eax*4+18h]` is
`queue[n-1]` — the back the port already compared against — and
`[esi+eax*4+1Ch]` is `queue[n]`.

**(3), the idle word**, is settled by `sub_4A7A20` (0x004A7A20), the only
producer of that word:

```c
    *a3 = 0;
    if (!a2)                       /* a2 is the raw device mask */
      *a3 = 0x40000000;
```

then one OR per bound key. It is never 0. So 0 is free, and
`channel.h` now names it `kQueueDrives` with a documented contract — "there is
no device this tick, the queue is the input" — which stands in for the engine's
**flag-0x80 path**, where `Cef_TickChannel` skips the poll altogether
(`if ((v5 & 0x81) != 0) { queue = [idle]; }` and the input pass gated on
`(u8(v1,4) & 0x81) == 0`). `stats().queueDriven` counts every tick that takes
it, so a caller that meant to pass a device word and passed 0 shows up as a
number instead of silently working; `tick`'s comment says a keyboard caller
must pass `kIdleInput`.

**A second gap fell out of porting the first.** `GoToMove` ends its entry pass
with `if (to->flags & 0x800) to->gotoState = from;` — the DYNAMIC RETURN EDGE,
written straight into the engine's own loaded copy of the file, so every later
read of that entry's GoTo sees it. `channel.cpp` wrote it into `dynamicReturn_`
and **read it nowhere**: all eight GoTo reads took the authored `gotoIdx`. That
cost nothing while the queue rules were missing and **956 bad landings** the
moment they landed — `Sham`'s `SH_STAND` reaches two nameless flag-0x800
aliases (flags `0xC0084813`) whose authored GoTo is 0, which read statically is
a landing on nothing and in the engine a null deref, so it cannot be what the
engine does. `CefChannel::gotoOf` is now the single read.

## 7. `docs/ASSETS.md` — the `.CTL` transition model

After "One matcher, per-bank meanings; `0x80000000` stays the no-input sentinel
for the idle/return edges. `verify.py: ctl transitions`.", a new block:

**How a press gets INTO the queue — the commit** (`Cef_TickChannel`
0x004A853A..0x004A85B3, 29_win32.c 300-320). The word the tick polled is not
pushed unconditionally. It is committed only when the state's flag `0x1000` is
clear or an edge is still open for what remains of it after the latch and the
walker-edge loop have masked their bits, and only when it **differs from the
last word committed** (`+20`); a word wholly consumed becomes the idle word
`0x40000000`, and a queue already 16 deep drops it. Then two rules, both of
which decide *when* a press takes effect rather than whether:

* **a lone idle word is DROPPED.** `if (n == 1 && (queue[0] & 0x40000000)) {
  queue[0] = 0; n = 0; }` — the test is on the bit, not on equality.
  `SetPersoBankGroup`'s memset, and entry flags `0x1000000`/`0x4000000`, all
  leave the queue holding exactly that one word, and the queue pass reads only
  the FRONT — so without the drop the first press of a bank sits behind a word
  that opens nothing and waits for something to pop it. With it, the press is
  at the front and acts on the tick it arrived.
* **entry flag `0x20000000` CUTS the queue to one** when more than one word is
  queued, and does not push at all: the state refuses to accumulate a buffer of
  presses behind it. 21 of the 1286 shipped entries carry the flag — `HKWALK`,
  `HFWALK`, `H_SNKON`, `H_IN_WO`, `L_HGUARD`, `MC_STAND`, `MC_WALK`,
  `SH_KSTEP` among them, all of them gaits or guards.

* **and the push itself dedupes against the BACK**, not the front:
  `if (!n || queue[n-1] != word) queue[n++] = word;`.

**Nothing held is the idle word, and it is never 0.** `sub_4A7A20`
(0x004A7A20) opens `*a3 = 0; if (!a2) *a3 = 0x40000000;` and then ORs one bit
per bound key, so the word `Cef_TickChannel` commits is either a bitfield or
`0x40000000`. The same function swaps bits 0 and 1 under channel flag 8 — the
reverse gait reverses left and right. (`engine/src/actor/channel.h` names 0
`kQueueDrives` for the engine's *other* input path, flag `0x80`, where the poll
is skipped entirely and the queue is the only source.)

**And an entry's GoTo can be REWRITTEN at runtime.** `GoToMove` ends its entry
pass with `if (to->flags & 0x800) to->gotoState = from;` — a **dynamic return
edge**, straight into the engine's own loaded copy of the file — so every later
read of that entry's GoTo (the alias chase, the clip-end fall-through, the
`0x8000` skip, the `0x10000` phase-match target) sees where the state was
entered from and not what the file says. Two entries of `Sham.CTL`
(flags `0xC0084813`, reached from `SH_STAND`) ship with **no** authored GoTo at
all and are only reachable *because* of it. `verify.py: engine actor states`.

Also worth a line under the existing "**And there is a second, confusable
value**" paragraph: the idle word is not only what `Perso_SetInputEnabled`
resets to, it is what the commit above **removes** when it is alone — which is
why a bank that has just been set up responds to the first key on the first
frame.

  pass while `flags & 0x81`, which is how the fight AI drives an NPC whose
  channel shares the one global `sub_43E080` poll. `run_actor_states` models
  that with `kQueueDrives` instead of with the flag; the two agree on the queue
  and differ on what the input pass does with the idle word, and nothing has
  been measured either way. Left as a note in `todo/actor-runtime.md`.
* **Rule (2) has no behavioural consequence anywhere in this corpus.** It fires
  4088 times in the main sweep and changes nothing there; only a hand-built
  case sees it, and that case reaches 9 of the 21 entries carrying the flag
  (the rest are pass-throughs or aliases that `GoToMove` walks straight past).
  What the rule is FOR — which press a gait or a guard is meant to refuse — is
  not established.
* **The dynamic return edge is per channel here, not per file.** The engine
  writes it into the shared loaded copy, so one actor's transition rewrites an
  entry for every actor of that bank. The replica keeps it per channel because
  `CtlFile` is const and shared. No shipped case is known where the difference
  shows, and none was looked for.
* **Whether the two rules make the game FEEL right** is not claimed and cannot
  be from here: the channel has no oracle (`traces/fight.log` proved combat is
  silent to the tag logger) and the standard stays **data-constrained**.
