## 1. What changed

### `o3de/camedit.{h,cpp}` — the sampler
`readCamFile` parsed chunk 10 and nothing sampled it. Added
`sampleCamEditing(file, editing, t, CamSample&)`, a transcription of
`Cam_PlayEditing` (0x0049ECE0) and its slope helper (0x0049EC10): tracks laid
end to end, each owning `[base, base + its last key's frame)`; inside a track
the bracketing pair of keys gives two whole cameras and every field (eye
`+16`, target `+28`, roll `+40`, fov `+44`) is `(c1 - c0) / (f1 - f0) * (t -
base - f0) + c0`. False in the engine's two give-up cases: `t >= duration`
(it returns 1 having written nothing) and no track brackets `t` ("key not
found for frame %2.2f"). Plus `editingForObject` (the `+28` target ==
object `handle >> 16` link `Script_LinkCamEditing` makes) and `editingById`.

### `script/scenerunner.{h,cpp}` — the scene's half of mode 13
* `load` now reads chunk 10 (`readScxStream` → `readCamFile`) into `cam_`.
* `start` records an `ActiveEditing` when the started object has a linked
  editing — `ScriptObject_HasCamEditing`'s answer — with program index,
  object array index/id/name, editing id/name, duration, start tick.
* `handle` fills its `travel` from the call's LAST field as `max(field, 0)`.
  The 46 handler (0x00402C30; 57–60 are the same tail):
  ```
  call sub_41D9C0 ; HasCamEditing   test eax,eax ; jz loc_402D08
  test edi,edi ; jge loc_402CDB ; mov [esp+10h],0
  loc_402CDB: fild dword ptr [esp+10h] ; push offset dword_930800 ; push 0Dh
  mov dword_93081C,1 ; mov dword_930828,-1 ; fstp dword_930818 ; call Camera_Request
  ```
  so the field is `fild`/`fstp`'d into request `+24` as a FLOAT, which
  `sub_414A90` reads as the move's duration in frames.
* `activeEditing()`: the last running program in OBJECT-ARRAY order whose
  clock is under its editing's duration (`Script_PlayAllScripts` walks the
  array; each `Script_PlayScript` sets the scene's active camera, so the
  last setter wins). `editingClock()` is the clock the frame on screen was
  sampled at — `Script_PlayScript` samples then advances, `Program::tick`
  has already advanced when a frontend asks, hence `clock - lastDt`.
  `editingCamera()` = `Cam_PlayEditing` at that clock.
* What mode 13 IS, read for this: `Camera_Request(13)` loads the mode-13
  preset (04_sys.c 918: a follow camera with `0x1008` in the flag word), and
  the camera tick (04_sys.c 3704) in mode 13 copies eye/target/fov/roll out
  of `dword_9103D4` every frame; `dword_9103D4` is `Scene_GetActiveCamera`
  after `Script_PlayAllScripts` (05_sys.c 2136). When it is 0 and the mode
  is still 13, the same loop does `Camera_Request(0, …)` with `+24 = 0`
  (05_sys.c 2140–2148): the fall-back is a CUT to the player camera.

### `backends/sdl/play.cpp`
* (12) The render section takes `session.scene().activeEditing()` /
  `editingCamera()`: while an editing drives, `view.cam` is the editing's
  eye/at/fov at the object's clock, superseding the mode-12 world camera;
  `drawWorld` is true on an editing even when no world camera resolves. The
  travel blends linearly from the camera LAST DRAWN over `travel` frames of
  the editing's clock (`sub_414A90` sets the duration; the from-camera is
  `g_CameraPrev`, which is what was on screen); with nothing drawn yet it is
  a cut, as the engine's travel 0 is. Announces once per take-over with the
  frame number and once when it ends ("falls back to world camera N"). Roll
  is sampled and NOT applied: `RCamera` has no roll; said in the print.
* (11) `walk->closed()` no longer `break`s: it prints, calls
  `session.answerUi(-1)`, resets the walk and runs on.
